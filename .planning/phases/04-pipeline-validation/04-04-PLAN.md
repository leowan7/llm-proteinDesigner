**Dockerfile** — Based on the official RFantibody repo (uses uv for package management):

```
FROM nvidia/cuda:11.8.0-cudnn8-devel-ubuntu22.04

RUN apt-get update && apt-get install -y wget git curl python3.10 python3-pip && rm -rf /var/lib/apt/lists/*

# Install uv (used by RFantibody's official setup)
RUN curl -LsSf https://astral.sh/uv/install.sh | sh

# Clone RFantibody
RUN git clone https://github.com/RosettaCommons/RFantibody.git /opt/rfantibody
WORKDIR /opt/rfantibody

# Install dependencies via uv (per RFantibody's official Dockerfile pattern)
RUN uv sync || pip install -e .

# Download all model weights (RFdiffusion antibody, AbMPNN, RF2 antibody)
RUN bash include/download_weights.sh

# Install Pod pipeline script deps
RUN pip install runpod requests

COPY run_pipeline.py /opt/run_pipeline.py
CMD ["python3", "/opt/run_pipeline.py"]
```

If RFantibody provides its own Dockerfile, prefer extending that. Check that the official `include/download_weights.sh` downloads:
- RFdiffusion antibody fine-tuned weights
- AbMPNN weights
- RF2 antibody-antigen validation weights

If RF2 fails at runtime, apply the fix from research: modify `src/rfantibody/rf2/config/base.yml` to set `model_weights: /home/weights/RF2_ab.pt` (or wherever the weights are downloaded to).

**run_pipeline.py** — Pod pipeline script for 3-stage VHH/scFv antibody design:

1. **Download input**: Target PDB from R2 presigned GET URL to `/tmp/target.pdb`.

2. **Stage 1 — RFdiffusion (antibody fine-tune)**: CDR loop generation
   - Extract from job_spec: epitope_residues, cdr_design (default H1/H2/H3), framework (VHH/scFv), num_designs
   - Run RFdiffusion with antibody-specific weights and CDR loop diffusion settings
   - The exact CLI invocation depends on RFantibody's interface — check the repo's README for the run command
   - Likely: `python scripts/run_rfantibody.py --target /tmp/target.pdb --epitope A30,A55 --cdr H1,H2,H3 --framework VHH --num_designs 100`
   - Output: CDR-designed antibody backbone PDBs

3. **Stage 2 — AbMPNN sequence design**: Assign sequences to CDR loops
   - Fix framework residues, design CDR loop residues
   - Uses AbMPNN weights (not vanilla ProteinMPNN)
   - Run via RFantibody's integrated pipeline or separate subprocess

4. **Stage 3 — RF2 antibody validation**: Predict antibody-antigen complex
   - Uses fine-tuned RoseTTAFold2 for antibody-antigen complexes
   - Extract confidence scores from RF2 predictions
   - Rank candidates by RF2 confidence

5. **Parse outputs**: Collect design PDBs + RF2 scores into candidates list
   - Scores: rf2_confidence, cdr_geometry (loop RMSD or similar)
   - Write metrics CSV with columns: rank, design_name, rf2_confidence, cdr_h3_length, sequence

6. **Upload outputs**: Upload PDBs + metrics CSV to R2 via presigned PUT URLs.

7. **Return**: `{"candidates": [...], "candidate_count": N, "next_steps": "Recommended: construct yeast display library with top CDR sequences for FACS screening."}`

Note: RFantibody may have an integrated pipeline that runs all 3 stages in one command. Check the repo's run scripts and adapt accordingly — avoid reimplementing what the tool already chains together.
