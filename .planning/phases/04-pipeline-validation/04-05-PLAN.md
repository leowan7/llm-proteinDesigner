**Dockerfile** — BoltzGen is available as a PyPI package (`pip install boltzgen`):

```
FROM nvidia/cuda:12.1.0-cudnn8-runtime-ubuntu22.04

RUN apt-get update && apt-get install -y python3.12 python3-pip wget && rm -rf /var/lib/apt/lists/*

# Install BoltzGen from PyPI
RUN pip install boltzgen

# Pre-download model weights (~6 GB) by running a dummy command
# BoltzGen auto-downloads to ~/.cache on first run
ENV HF_HOME=/opt/cache
RUN mkdir -p /opt/cache
# Trigger weight download during build (may need a minimal run)
RUN boltzgen --help || true
# If weights don't download from --help, run a minimal design:
# RUN echo "entities: [{sequence: 'AAAAAA'}]" > /tmp/dummy.yaml && \
#     boltzgen run /tmp/dummy.yaml --output /tmp/dummy_out --num_designs 1 --budget 1 || true

# Install RunPod handler deps
RUN pip install runpod requests pyyaml

COPY rp_handler.py /opt/rp_handler.py
CMD ["python3", "/opt/rp_handler.py"]
```

If BoltzGen's repo has its own Dockerfile, prefer extending that. The key is baking weights into the image so there is no runtime download. Verify the weight download mechanism and trigger it during build.

**Critical**: BoltzGen requires CIF format with chains starting at residue index 1. The handler must verify this or re-index using gemmi if needed. Install gemmi in the Docker image: `pip install gemmi`.

**rp_handler.py** — RunPod handler for BoltzGen:

1. **Download input**: Target file from R2 presigned GET URL to `/tmp/target.cif`.
   - BoltzGen requires CIF, not PDB. The Kendrew backend should ensure the file is CIF at upload time (Phase 2 normalization). If a .pdb is received, convert using gemmi.
   - Re-index CIF so each chain starts at residue 1 using gemmi (required by BoltzGen — see Pitfall 2 in research).

2. **Generate YAML design spec**: Write `/tmp/design_spec.yaml` from JobSpec:
   ```yaml
   entities:
     - file:
         path: /tmp/target.cif
         include:
           - chain:
               id: {target_chain}
   binder:
     length: [{min_length}, {max_length}]
     hotspots:
       - chain: {target_chain}
         res_index: {min_hotspot}..{max_hotspot}
   ```
   Adapt based on BoltzGen's actual YAML schema (check docs).

3. **Run BoltzGen**: Subprocess call:
   ```
   boltzgen run /tmp/design_spec.yaml \
     --output /tmp/boltzgen_output \
     --protocol {protocol} \
     --num_designs {num_designs} \
     --budget {budget}
   ```
   Default protocol: `protein-anything`. Budget from `parameters.budget` (default 20).

4. **Parse outputs**: BoltzGen writes to output directory:
   - `final_ranked_designs/` — ranked design PDB/CIF files
   - `final_designs_metrics_N.csv` — metrics for ranked candidates
   - Extract scores: refolding_rmsd, ipTM, pLDDT
   - Rank candidates by composite score (ipTM descending, then refolding_rmsd ascending)

5. **Upload outputs**: Upload ranked PDBs + metrics CSV to R2.

6. **Return**: `{"candidates": [...], "candidate_count": N, "next_steps": "..."}`
   - next_steps: Recommend SPR/BLI binding assay, BLAST-check designs in 73-76 aa range for ubiquitin contamination.

Known issue to handle: If designs are in 73-76 aa length range, add a warning in the return payload about ubiquitin contamination risk.
