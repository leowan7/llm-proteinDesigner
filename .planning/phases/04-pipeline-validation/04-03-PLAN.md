**Dockerfile** — Based on FreeBindCraft's official build process:

```
FROM nvidia/cuda:12.1.0-cudnn8-devel-ubuntu22.04

RUN apt-get update && apt-get install -y wget git python3.10 python3-pip && rm -rf /var/lib/apt/lists/*

# Clone FreeBindCraft
RUN git clone https://github.com/cytokineking/FreeBindCraft.git /opt/bindcraft
WORKDIR /opt/bindcraft

# Install with --no-pyrosetta (MIT license)
RUN bash install_bindcraft.sh --cuda '12.1' --no-pyrosetta

# Pre-download AF2 weights (~3.5 GB) by triggering a minimal run during build
# This bakes weights into the image so no runtime download needed
RUN python3 -c "from colabfold.download import download_alphafold_params; download_alphafold_params('alphafold2_multimer_v3')" || true

# Install Pod pipeline script deps
RUN pip install runpod requests

COPY run_pipeline.py /opt/run_pipeline.py
CMD ["python3", "/opt/run_pipeline.py"]
```

If the FreeBindCraft repo includes its own Dockerfile, prefer extending that with the runpod additions. The key constraint: `--no-pyrosetta` must be used during install AND at runtime.

**run_pipeline.py** — Pod pipeline script for BindCraft:

1. **Download input**: `requests.get(input_presigned_url)` -> `/tmp/target.pdb`

2. **Generate settings JSON**: Write target.json to `/tmp/target.json`:
   ```json
   {
     "design_path": "/tmp/outputs/",
     "binder_name": "design",
     "starting_pdb": "/tmp/target.pdb",
     "chains": "{target_chain}",
     "target_hotspot_residues": "{comma-separated hotspots}",
     "lengths": [min_length, max_length],
     "number_of_final_designs": num_designs
   }
   ```

3. **Run BindCraft**: Single subprocess call:
   ```
   python bindcraft.py \
     --settings /tmp/target.json \
     --filters settings_filters/default_filters.json \
     --advanced settings_advanced/default_4stage_multimer.json \
     --no-pyrosetta --no-plots --no-animations
   ```
   Note: BindCraft is a single monolithic execution — all 4 stages (hallucination, MPNN, AF2 monomer, interface analysis) run within this one command. Timeout: 4 hours via RunPod policy.

4. **Parse outputs**: BindCraft writes to `design_path`:
   - `final_designs/` — ranked PDB files
   - Metrics in CSV or per-design score files
   - Parse scores: ipTM, pLDDT, binder_RMSD, shape_complementarity, SAP_score, interface_buried_sasa
   - Handle zero-output case: if `final_designs/` is empty, return `{"candidates": [], "candidate_count": 0, "zero_output": true, "next_steps": "..."}`

5. **Upload outputs**: Upload each final design PDB + metrics CSV to R2 via presigned PUT URLs.

6. **Return**: Candidates list with scores, or zero_output response.

Error handling: BindCraft can fail at various stages. Capture stderr, check for common failures (CUDA OOM, filter rejection). Return informative error messages.

Important: Set `ulimit -n 65536` either in Dockerfile (`ulimit` in CMD) or via `--ulimit nofile=65536:65536` in RunPod template config (document this in the handler comments).
