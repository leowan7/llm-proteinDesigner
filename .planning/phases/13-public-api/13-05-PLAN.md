<objective>
Round out the bindwave-python SDK with the async half + cursor auto-paginator + Job.wait_until_complete + Job.download_results convenience methods. AsyncClient mirrors sync Client's surface via httpx.AsyncClient + the same exception parser + retry policy. `client.jobs.iter_all(**filters)` is a generator that walks the cursor until next_cursor is None (sync); `iter_all_async` is the async variant. `Job.wait_until_complete(poll_every=30, timeout=None)` polls `client.jobs.get(self.id)` in a loop until status terminal-set; respects timeout. `Job.download_results(dest_dir=Path('./'))` iterates candidates, fetches each candidate's 24h presigned download_url via httpx, writes to `dest_dir/{job_id}-candidate-{rank}.pdb`, returns dict {rank: Path}.

Purpose: The SDK ships with the headline convenience methods users expect from a production SDK: typed pagination, polling-until-done, downloading results. Without these, every SDK user reinvents the polling loop on day one. This plan closes API-12 SDK requirements.

Output: 2 new SDK source files (_async_client.py, _pagination.py) + 2 modified sources (jobs.py adds Async variant + iter_all + wait_until_complete + download_results AND retrofits `_client` pinning on the existing sync submit/get/list/cancel methods that 13-04 just shipped; types/job.py adds the _client field plus methods to Job model) + 4 new test files + 2 new examples + __init__.py exports + CHANGELOG entry.

Note on intentional churn: the Job._client back-reference is declared and used in this plan rather than hoisted into Plan 13-04. Hoisting would require touching 4 method bodies on JobsResource (submit/get/list/cancel) inside 13-04's already-large jobs.py task to add `job._client = self._client; return job`, plus adding the `_client` field to types/job.py before Job has any methods that consume it. Documenting the churn here is cheaper than restructuring 13-04. The churn is well-bounded: 4 lines added to JobsResource (sync), 4 lines added to AsyncJobsResource (async), one Pydantic field on Job.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Job._client back-reference | Pydantic model holds an opaque reference to the client that created it; if model is serialized + deserialized (e.g. saved to JSON), the back-reference is lost and methods raise AttributeError. Document in Job docstring. |
| download_results presigned URL | The URL is a 24h presigned R2 URL; httpx.get downloads bytes; if URL is tampered (e.g. modified expiry), R2 rejects with 403 — exception propagates cleanly |
| AsyncClient asyncio.sleep retry | Retry path uses event-loop time; no thread safety concern |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-13-09 | Information disclosure | Job model serialization | accept | If user serializes Job to JSON for storage, _client back-reference is dropped (Pydantic Field exclude=True). Documented in Job docstring. Re-attach a client via `job._client = client` to call methods after deserialization. |
| T-13-06 | Denial of service | wait_until_complete polling | mitigate | poll_every default 30s prevents tight loops; timeout kwarg lets caller bound total wall-clock |
| T-13-06 | Denial of service | iter_all unbounded iteration | accept | Caller controls when to stop iterating. Documented in iter_all docstring: "Use `itertools.islice(iter_all(...), 1000)` to bound iteration in lazy mode." |
</threat_model>
