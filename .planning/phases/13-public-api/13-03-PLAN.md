<objective>
Land the /api/v1/jobs surface — the 4 endpoints that account for ~80% of SDK traffic. POST /api/v1/jobs (submit, Idempotency-Key required, co-transactional with launch_job), GET /api/v1/jobs (cursor-paginated org-scoped list with filters), GET /api/v1/jobs/{job_id} (inline candidates + 24h presigned URLs), POST /api/v1/jobs/{job_id}/cancel (org-scoped ownership check + delegate to cancel_job_by_id). Supporting modules: api/v1/cursor.py (opaque base64 encoder/decoder per RESEARCH §2.3 — NO HMAC signing), api/v1/idempotency.py (3-state Postgres lifecycle per RESEARCH §2.9 — try_begin / mark_complete / replay / 409 / 422), api/v1/errors.py (app-level RFC 7807 handler with `request.url.path.startswith("/api/v1/")` gate per RESEARCH §2.7), jobs/serialize.py (shared serializer extracted from webhooks/router.py per RESEARCH §5.13). Modifications: jobs/dispatch.py accepts optional `conn` parameter for co-transactional flow (RESEARCH §5.6); main.py wires the router include + 2 exception handlers + selects api_v1_limiter vs limiter via path-prefix logic (RESEARCH §5.4 — keep single SlowAPIMiddleware, do not register a second). Rate-limit headers (X-RateLimit-Limit / Remaining / Reset + Retry-After on 429) flow through the api_v1_limiter Limiter from Plan 13-02 — verify the single-limiter-decorator path avoids slowapi #33 double-headers bug.

Purpose: This is the headline endpoint surface. SDK demonstration relies on it. Everything in Wave 3 (auto-paginator, Job.wait_until_complete, frontend tab) reads from these endpoints.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Idempotency-Key header → DB | Header value flows untrusted into INSERT; treated as opaque string; composite PK (api_key_id, idempotency_key) means cross-org collision impossible |
| Request body → hash → DB | Body canonicalized then hashed; canonical form is sort_keys=True so reorder-but-same-content does NOT trigger 422 |
| Cursor parameter → query offset | Cursor decodes to (created_at, id) but the SQL WHERE clause is ALSO org-filtered, so tampered cursor cannot leak cross-org jobs |
| Job-ID path parameter → query | Service-layer cancel resolves billing via JOIN; router-level ownership check prevents cross-org cancel |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-13-03 | Elevation of privilege | Cross-org access via API key | mitigate | Every endpoint resolves org_id from require_role_api(...) and gates SELECT by `WHERE organization_id = $1`; GET single returns 404 (not 403) on miss to avoid existence-disclosure |
| T-13-04 | Tampering | Idempotency-Key collision attack | mitigate | Composite PK (api_key_id, idempotency_key) — keys from org-A cannot collide with org-B; request_body_hash check prevents same-key-different-body misuse → 422 |
