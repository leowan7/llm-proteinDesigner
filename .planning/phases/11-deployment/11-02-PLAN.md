**Block A — Supabase Free-tier projects (expected ~15 min; no billing on Free tier; upgrade to Pro before public launch):**
1. Go to supabase.com/dashboard, click "New project".
2. Name: `kendrew-prod`. Region: `us-east-1` (matches R2 default). Plan: Free ($0/mo; upgrade to Pro before public launch for PITR + non-paused DBs). Set DB password (store in PROVISIONING.md).
3. Wait for provisioning. Go to Project Settings → Database → Connection string → Transaction pooler (port **6543**). Copy the `DATABASE_URL`.
4. Project Settings → API → copy Project URL, anon public, service_role.
5. Project Settings → API → JWT Settings → copy JWT secret.
6. PITR not available on Free tier — daily backup auto-enabled (7-day retention). Re-enable this step when upgrading to Pro before public launch.
7. Repeat steps 2-6 for `kendrew-staging`.
8. Paste all values into PROVISIONING.md §Supabase.

**Block B — Upstash Redis (expected ~5 min):**
1. Go to console.upstash.com → Redis → Create Database.
2. Name: `kendrew-prod`. Type: Global. TLS: **Enabled** (default). Region: US-East-1.
3. Copy REDIS_URL — confirm it starts with `rediss://` (TLS scheme, double-s).
4. Repeat for `kendrew-staging`.
5. Paste into PROVISIONING.md §Upstash.

**Block C — Cloudflare R2 buckets + API tokens (expected ~10 min):**
1. Cloudflare dashboard → R2 → Create bucket: `kendrew-prod`. Default (private).
2. Create bucket: `kendrew-staging`. Default (private).
3. R2 → Manage R2 API Tokens → Create API token.
   - Name: `kendrew-prod-r2`. Permissions: Object Read & Write. Specify bucket: `kendrew-prod` only. TTL: no expiry.
4. Copy Access Key ID + Secret Access Key + Endpoint URL. Paste into PROVISIONING.md.
5. Create second token `kendrew-staging-r2` scoped to `kendrew-staging` only.
6. Verify buckets are PRIVATE (no public bucket access — R2 default).

**Block D — Modal staging environment + tokens (expected ~5 min):**
1. Locally (Leo's machine): `modal environment create staging` (main already exists).
2. Run `modal token new --profile kendrew-ci` (or use existing token). Copy MODAL_TOKEN_ID + MODAL_TOKEN_SECRET.
3. `modal secret create --env main kendrew-r2 S3_ENDPOINT_URL=... S3_ACCESS_KEY=... S3_SECRET_KEY=... S3_BUCKET_NAME=kendrew-prod` (use prod R2 token from Block C).
4. `modal secret create --env staging kendrew-r2 S3_ENDPOINT_URL=... S3_ACCESS_KEY=... S3_SECRET_KEY=... S3_BUCKET_NAME=kendrew-staging` (use staging R2 token).
5. Paste tokens into PROVISIONING.md.
6. Note: token values are also set as GitHub repo secrets in Plan 11-03.

**Block E — Cloudflare DNS API token (expected ~3 min):**
1. dash.cloudflare.com/profile/api-tokens → Create Token → Custom token.
2. Name: `kendrew-dns-edit`. Permissions: Zone → DNS → Edit. Zone Resources: Include → Specific zone → `bindwave.com`.
3. Copy token + note Zone ID from the bindwave.com overview page. Paste into PROVISIONING.md.

**Block F — Resend domain verification (expected ~10 min + DNS propagation wait):**
1. resend.com/domains → Add Domain → `bindwave.com`.
2. Resend shows required DNS records (SPF TXT, DKIM TXT, DMARC TXT, optional MX).
3. Add each record to Cloudflare DNS (bindwave.com zone). For MX records and `_dkim`/`_domainkey` hostnames, use DNS-only (grey cloud) per Pitfall 6.
4. Click "Verify Domain" in Resend — may take up to 1 hour.
5. If DKIM will not verify after 1 hour, check for stray NS records at `_dkim` or `_domainkey` and delete them (Pitfall 6).
6. resend.com/api-keys → Create API Key → scope: Sending access for bindwave.com only. Copy key into PROVISIONING.md.
