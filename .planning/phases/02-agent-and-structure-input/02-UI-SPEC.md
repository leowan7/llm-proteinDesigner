## Spacing Scale

Declared values (must be multiples of 4). Source: 8-point scale default; confirmed consistent with Phase 1 auth screen patterns (`gap-2`, `px-4`, `py-4` observed in existing components).

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline spacing between badge icons and text |
| sm | 8px | Compact element spacing, button icon-to-label gaps |
| md | 16px | Default element spacing, card internal padding, form field gaps |
| lg | 24px | Section padding within cards (ReviewCard, ValidationCard) |
| xl | 32px | Layout gaps between chat and side panels |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing |

Exceptions:
- Chat input touch target minimum: 44px height (accessibility — iOS touch target requirement)
- Message bubbles: 8px (`sm` token) top/bottom padding (compact density; aligns with standard scale)

## Typography

Source: detected from existing components (`text-xl font-semibold leading-[1.2]`, `text-base font-normal leading-[1.5]`, `text-sm`, `text-xs`) in Phase 1 auth screens and shadcn component primitives.

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Body | 16px (text-base) | 400 (normal) | 1.5 | Agent chat message text, input text, card descriptions |
| Label | 14px (text-sm) | 400 (normal) | 1.4 | Form labels, secondary info, muted foreground text, card footers |
| Heading | 20px (text-xl) | 600 (semibold) | 1.2 | Card titles (ReviewCard, ValidationCard, StructurePreviewCard), page section headings |
| Display | 28px (text-2xl) | 600 (semibold) | 1.2 | Phase-level page heading only — "Design a Protein" on ChatPage |

Font weights: exactly 2 — regular (400) and semibold (600). Source: `@fontsource/inter/400.css` and `@fontsource/inter/600.css` imported in globals.css.

Monospace exception: PDB residue identifiers and accession IDs (e.g., `P08887`, `1N26`, residue `100A`) are rendered in `font-mono text-sm` (14px, system monospace stack via Tailwind). This applies inline within agent messages and in the StructurePreviewCard residue count field.

## Color

Source: detected from globals.css dark mode `.dark` block. App renders dark mode by default (confirmed in Phase 1 CONTEXT and shadcn setup). All color values are oklch; approximate hex provided for readability only — use CSS variables in code.

**Color split: 60% dominant / 30% secondary / 10% accent**

| Role | CSS Variable | Dark Mode oklch | Approx Hex | Usage |
|------|-------------|-----------------|------------|-------|
| Dominant (60%) | `--background` | oklch(0.145 0 0) | #1a1a1a | Page background, ChatPage canvas |
| Secondary (30%) | `--card` | oklch(0.205 0 0) | #232323 | Message bubbles, ReviewCard, ValidationCard, StructurePreviewCard |
| Accent (10%) | `--primary` | oklch(0.585 0.233 277.117) | ~indigo-500 | Reserved for: primary CTA buttons only (Launch Job, Confirm), focus rings, active inline action buttons |
| Destructive | `--destructive` | oklch(0.704 0.191 22.216) | ~red-400 | Validation fail badges, hard-block alert text, destructive action buttons |

Semantic status colors (for ValidationCard badges only — do not use as general accent):

| Status | Color | Implementation |
|--------|-------|----------------|
| pass | `text-green-400` (Tailwind) | Badge with pass icon |
| warn | `text-yellow-400` (Tailwind) | Badge with warn icon; user must acknowledge |
| fail | `text-destructive` (CSS var) | Badge + Alert component; blocks dispatch |

Accent reserved for: primary CTA buttons ("Launch Job", "Confirm Tool Choice"), focus rings on chat input and inline action buttons. Never apply accent to neutral informational elements, status badges, or message bubbles.

## Component Inventory

All components are new for Phase 2. Each maps to a file in `frontend/src/components/chat/`.

### ChatPage

Full-width authenticated layout. Replaces the centered `AuthLayout` card pattern from Phase 1.

- **Layout:** 2-column on desktop (chat thread left, 60% width; context panel right, 40% width — context panel hidden on mobile). On mobile, single column, context panel slides up as a sheet when triggered.
- **Left column:** MessageList (top, flex-grow, scrollable) + ChatInput (bottom, sticky).
- **Right column:** Displays the most recent structured card (StructurePreviewCard, ReviewCard, or ValidationCard) as a persistent reference panel.
- **Header:** App name left-aligned, "New Session" ghost button right-aligned.

### ChatInput

Wraps shadcn/ui AI `chat/chat-input` component.

- **Height:** 44px minimum (touch target), auto-expands up to 120px for multi-line.
- **Placeholder text:** `"Describe your design goal, paste a PDB ID, or drop a .pdb / .cif file"`
- **Drag-drop zone:** Activated when a `.pdb` or `.cif` file is dragged over the input area. Visual cue: border color shifts to `--primary`, text becomes `"Drop PDB file to upload"`. Only one file at a time.
- **File attachment preview:** After drop, show a pill badge below the input: filename + file size + X to remove. Pill uses `--secondary` background.
- **Send button:** Icon-only (lucide `SendHorizontal`), `aria-label="Send message"`, `--primary` background, 36px width, right edge of input.
- **Disabled state:** Send button disabled and input grayed while agent is processing (SSE stream active).

### MessageList

Wraps shadcn/ui AI `chat/chat-message-list`.

- **Auto-scroll:** Scrolls to newest message on append. Scroll position is preserved on upward scroll (user reviewing history).
- **Message bubbles:** User messages right-aligned, `--secondary` background, `--foreground` text. Agent messages left-aligned, `--card` background with `ring-1 ring-foreground/10`.
- **Typing indicator:** Displayed while SSE stream is active. Three animated dots in a left-aligned bubble. Located immediately below the last agent message.
- **Status line:** Single line of `text-sm text-muted-foreground` directly below the typing indicator. Displays the most recent status event from SSE (e.g., `"Fetching structure from RCSB..."`, `"Analyzing your design goal..."`). Updates in place; does not create new bubbles.
- **Greeting message:** Agent sends an opening message on ChatPage mount, before any user input. Rendered as a full-width centered card (not a bubble) with copy specified in Copywriting Contract.

### AgentMessage

Renders within the left-aligned agent bubble. Content may include:

- Plain markdown text (bold, inline code, bullet lists). Renderer: standard markdown-to-JSX.
- Inline action buttons: 2-4 `variant="outline"` buttons below the message text. Each maps to a specific confirmation action (e.g., "Yes, use BindCraft", "Let me change something"). Max 4 buttons per message; single-row on desktop, wraps on mobile.
- Embedded structured cards (StructurePreviewCard, ReviewCard, ValidationCard) — rendered inline within the message thread when the agent produces them.

### StructurePreviewCard

Shown inline in the chat thread after a structure is resolved (INPUT-02, INPUT-03, INPUT-04).

- **Container:** shadcn `Card` component, `data-size="sm"` for compact layout.
- **Fields displayed:**
  - PDB ID (monospace, `text-sm`)
  - Protein name (body text)
  - Resolution (e.g., `"2.40 Å"` or `"N/A (NMR)"`)
  - Experimental method (e.g., `"X-ray"`, `"NMR"`, `"EM"`)
  - Chain count + selected chain (e.g., `"4 chains — using chain A"`)
  - Residue count
  - Normalization summary (if changes were made): collapsible `<details>` element, closed by default, showing bullet list of changes made (e.g., `"Converted 3 MSE residues to MET"`, `"Selected model 1 of 12 (NMR)"`)
- **Override action:** A `variant="ghost" size="sm"` button `"Use a different structure"` below the card. Opens a text input inline for the user to specify an alternative.

### ReviewCard

The critical pre-launch confirmation card (AGENT-02 confirmation, AGENT-03 wizard completion). Shown inline in chat and mirrored in the right context panel.

- **Container:** shadcn `Card` with a distinct `ring-2 ring-primary/30` border to draw attention.
- **Sections:**
  - Design goal (plain-language summary of what the agent understood)
  - Tool selected (e.g., `"BindCraft"`) with one-sentence rationale
  - Target structure (PDB ID + chain)
  - Hotspot residues (comma-separated list in monospace, or `"None specified"`)
  - Parameters (name: value pairs, one per line; 3-5 items)
  - Estimated cost (e.g., `"~$4.20 — ~90 min GPU"`)
- **Actions:** Two buttons below the card:
  - `"Launch Job"` — `variant="default"` (accent background), full-width on mobile.
  - `"Edit parameters"` — `variant="outline"`, opens the wizard back to the parameters step.
- **Disabled state:** Both buttons disabled until all validation checks complete. `"Validating..."` text replaces button labels during this period.

### ValidationCard

Shown inline in chat after pre-flight validation runs (AGENT-04, AGENT-05).

- **Container:** shadcn `Card`.
- **Content:** A checklist. Each row: status icon + check name + one-sentence message.
  - pass: `CheckCircle` lucide icon, `text-green-400`.
  - warn: `AlertTriangle` lucide icon, `text-yellow-400`.
  - fail: `XCircle` lucide icon, `text-destructive`.
- **Fail state:** If any check is `fail`, a shadcn `Alert` component (destructive variant) appears below the checklist with the specific reason and what to fix. The "Launch Job" button in ReviewCard is disabled until fail is resolved.
- **Warn acknowledgment:** If any check is `warn` and none are `fail`, a `"Proceed with warnings"` `variant="outline"` button appears below the checklist. The user must click this before "Launch Job" becomes active. Button text changes to `"Warnings acknowledged"` (disabled) after click.

## Copywriting Contract

Source: CONTEXT.md specifics + requirements. All copy written for a technical-scientist audience (CLAUDE.md brand voice). No hedging language, no over-explanation.

| Element | Copy |
|---------|------|
| Primary CTA | "Launch Job" |
| Greeting heading | "What are you designing today?" |
| Greeting body | "Describe your target protein, paste a PDB or UniProt accession, or drag in a .pdb file. I'll identify the right tool and guide you through the parameters." |
| Empty MessageList (no greeting yet) | (not applicable — agent greets first; no user-facing empty state) |
| New session confirmation | "Start new session? Your current conversation will be cleared." |
| Structure resolved success | (inline in agent message — Claude's discretion per CONTEXT.md) |
| Validation pass summary | "Pre-flight checks passed. Ready to launch." |
| Validation warn prompt | "Proceed with warnings" |
| Validation fail heading | "Cannot proceed — fix the following:" |
| Hard block: wrong file format | "This file doesn't appear to be a valid PDB or mmCIF structure. Check that the file is not truncated and retry." |
| Hard block: empty chain | "Chain [X] contains no standard amino acid residues. Select a different chain or upload a corrected structure." |
| Hard block: no target residues | "No target residues could be identified in the selected chain. Provide hotspot residues or select a different chain." |
| RCSB fetch error | "Could not fetch [PDB ID] from RCSB. Verify the accession and try again, or upload the file directly." |
| UniProt search no results | "No reviewed UniProt entries matched '[query]'. Try a more specific name or provide a PDB accession directly." |
| Agent thinking status (rotating) | "Analyzing your design goal..." / "Fetching structure from RCSB..." / "Resolving UniProt entry..." / "Running pre-flight checks..." |
| Destructive: clear session | Confirmation: "Start new session? Your current conversation will be cleared." — inline confirm/cancel in chat header popover, no modal. |
| File drop active state | "Drop PDB file to upload" |
| File attached pill | "[filename.pdb] · [size KB]  ×" |
| Warn: NMR structure | "NMR ensemble detected — using model 1. X-ray structures generally give better results for binder design." |
| Warn: low resolution | "Resolution [X.X Å] is below 2.5 Å. Structure quality may affect design outcome." |
| Warn: buried hotspot | "Residue [N] ([RES]) appears buried (SASA=[X.X] Å²). This may not be a productive binder contact point." |
