Format: "Estimated GPU cost" label, then "$X.XX–$Y.YY estimated" in `font-mono`. Add disclaimer text below in `text-sm text-muted-foreground`: "Actual charge is based on GPU time consumed and may differ from this estimate."

b. **Launch Job button** (already exists per Phase 2 — modify its onClick handler):
- Set button to "Launching..." disabled state
- Call `getPaymentStatus()`
- If `has_payment_method === false`: redirect to Stripe Checkout via `createCheckoutSession(window.location.href)`, then `window.location.href = result.url`
- If `has_payment_method === true`: POST to a new backend endpoint `/jobs/launch` (see below) with the job spec
- On success: receive `{ job_id }`, call `onJobLaunched(jobId)` callback (prop from ChatPage)
- On Stripe Checkout return with `?setup=success` in URL: auto-retry the launch. On `?setup=cancelled`: show inline Alert: "A payment method is required to launch jobs. Add a payment method to continue."

c. **Cost breakdown** (shown before launch): When estimate is available, show 3 rows:
- "GPU compute": low-high range
- "Platform fee": "{markup}% platform fee"
- "Total": low-high range including markup

**2. Add POST `/jobs/launch` backend endpoint.** This can go in `backend/jobs/router.py` or a new section in `backend/agent/router.py`. The endpoint:
- Requires authenticated user
- Accepts `{ job_id: str }` (the existing job row from wizard)
- Calls `check_payment_method` via the billing module
- If no payment method: return 402 with `{"detail": "payment_required"}`
- If payment method: call `launch_job(job_id, job_spec, user_id, pool)`
- Return `{"job_id": job_id, "status": "queued"}`

**3. Update ChatPage.tsx** to handle job launch and status:

a. Add `onJobLaunched` callback that:
- Stores the active `jobId` in component state
- Subscribes to job status SSE via `subscribeToJobStatus(jobId, onEvent)`
- On SSE events while in chat: update a `jobStatus` state variable
- When terminal status received:
  - If "complete": add a `JobCompletionCard` to the chat messages (with design count, runtime, cost, link to `/jobs/{id}`)
  - If "failed": add a failure message card to chat
  - If "cancelled": add a cancellation confirmation to chat

b. Pass `onJobLaunched` as prop to ReviewCard

c. Add `JobStatusCard` inline in chat when job is running (small version, updates via same SSE subscription)

**4. Handle Stripe Checkout return in ChatPage.** Check URL params on mount:
- `?setup=success` → show success toast/alert, auto-retry launch
- `?setup=cancelled` → show the payment required alert on the ReviewCard
