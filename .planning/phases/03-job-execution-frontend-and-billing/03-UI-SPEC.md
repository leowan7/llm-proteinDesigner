## Spacing Scale

Declared values (multiples of 4 only). Tailwind v4 utility classes map directly.

| Token | Value | Tailwind Class | Usage |
|-------|-------|----------------|-------|
| xs | 4px | `p-1` / `gap-1` | Icon gaps, badge padding, inline chip spacing |
| sm | 8px | `p-2` / `gap-2` | Compact element spacing, card section gaps |
| md | 16px | `p-4` / `gap-4` | Default card padding (`px-4`), form field spacing |
| lg | 24px | `p-6` / `gap-6` | Card section breaks, major content group spacing |
| xl | 32px | `p-8` / `gap-8` | Between page-level cards on JobPage |
| 2xl | 48px | `py-12` | Page vertical breathing room (top/bottom padding) |
| 3xl | 64px | `py-16` | Not used in Phase 3 |

**Exceptions:**
- Stage progress indicator: 44px minimum touch target height (accessibility minimum for mobile web)
- Download buttons on CandidateCard: minimum 36px height (sm variant, `h-9`)

## Typography

All sizes use Inter. Only two weights are permitted in the codebase (400 and 600, loaded via `@fontsource/inter`).

| Role | Size | Weight | Line Height | Tailwind | Usage |
|------|------|--------|-------------|----------|-------|
| Body | 16px | 400 | 1.5 | `text-base` | Card body text, candidate descriptions, next-steps guidance |
| Label | 14px | 400 | 1.4 | `text-sm` | Metadata labels, form labels, muted field captions (`text-muted-foreground`) |
| Heading | 20px | 600 | 1.2 | `text-xl font-semibold` | Card section headings, page section titles |
| Display | 28px | 600 | 1.2 | `text-2xl font-semibold` | JobPage top-level heading (job tool name + status) |

**Monospace exception:** PDB IDs, residue codes, GPU cost values, and score values render in `font-mono text-sm` (system monospace stack) at weight 400. This matches the existing pattern in `StructurePreviewCard.tsx` and `ReviewCard.tsx`.

## Color

All values are CSS custom properties defined in `globals.css`. Use semantic tokens only — never raw oklch values in components.

| Role | CSS Token | Dark Value (oklch) | Usage |
|------|-----------|-------------------|-------|
| Dominant (60%) | `--background` | `oklch(0.205 0 0)` | Page background |
| Secondary (30%) | `--card` | `oklch(0.255 0 0)` | All cards (JobStatusCard, CandidateCard, RunSummaryCard, NextStepsCard), sidebar |
| Accent / Primary (10%) | `--primary` | `oklch(0.585 0.233 277.117)` (indigo-500) | See reserved-for list below |
| Destructive | `--destructive` | `oklch(0.704 0.191 22.216)` | Cancel job button (destructive variant only) |
| Muted | `--muted-foreground` | `oklch(0.708 0 0)` | All metadata labels, secondary text, empty state body |

**Accent (primary) reserved for:**
1. "Launch Job" button (primary variant)
2. "View full results" button in chat completion card
3. Active/current stage indicator in stage progress row
4. Focus rings (`--ring` maps to indigo-500)
5. `ring-2 ring-primary/30` on the pre-launch ReviewCard (existing pattern, carry forward)

**Accent is NOT used for:** candidate rank numbers, score values, download buttons, informational badges, the Run Summary card header, or the Next Steps card.

**Status badge colors** (use shadcn Badge component):
- Queued: `variant="secondary"` (muted, neutral)
- Running: `variant="default"` (primary/indigo — active state)
- Complete: use `bg-emerald-500/15 text-emerald-400` inline classes (success semantic, no shadcn variant for this)
- Failed: `variant="destructive"`
- Cancelled: `variant="secondary"` (same as queued — neutral terminal)

## Component Inventory

New components required for Phase 3. All follow the existing `Card > CardHeader > CardContent` pattern.

### JobStatusCard
**File:** `frontend/src/components/jobs/JobStatusCard.tsx`
**Purpose:** Shown inside the agent chat thread on job launch. Updates in real time via SSE. Also appears at top of `/jobs/{id}` page.
**Anatomy:**
- Stage progress row: discrete stages left-to-right separated by `→` — "Queued", "Initializing GPU", "Running [tool-specific]", "Scoring designs", "Complete". Current stage uses `text-primary font-semibold`. Future stages use `text-muted-foreground`. Completed stages use `text-muted-foreground line-through`.
- Tool-specific running stage label: "Running diffusion" (RFdiffusion/RFantibody) or "Running binding optimization" (BindCraft) or "Running structure generation" (BoltzGen).
- Status badge (top-right of card header): see status badge colors above.
- Cancel button: shown only when `status === "running"`. Destructive variant. Label: "Cancel job".

### RunSummaryCard
**File:** `frontend/src/components/jobs/RunSummaryCard.tsx`
**Purpose:** Top section of `/jobs/{id}` results page. Shows post-run metadata.
**Anatomy:**
- Tool name + run date (heading row)
- Key-value grid (2 columns, `text-sm`): Runtime, GPU cost, Designs generated, Parameters (collapsed collapsible matching normalization changes pattern from `StructurePreviewCard.tsx`)
- GPU cost display: `font-mono text-sm` — format: "$X.XX (N min on A100)"
- "Download all designs" button: `variant="default"`, label exactly "Download all designs"

### CandidateCard
**File:** `frontend/src/components/jobs/CandidateCard.tsx`
**Purpose:** One card per design candidate, ranked by primary score. Repeated N times on results page.
**Anatomy:**
- Rank badge: `#1`, `#2`, etc. — `text-sm font-semibold` in top-left of card header, no accent color
- Score grid: tool-native scores only, no custom metrics
  - RFdiffusion/RFantibody: pAE, pLDDT
  - BindCraft: binding energy (kcal/mol), iPAE
  - BoltzGen: confidence score
- Score values: `font-mono text-sm text-foreground`
- Score labels: `text-sm text-muted-foreground`
- Individual download button: `variant="outline" size="sm"`, label "Download PDB"

### NextStepsCard
**File:** `frontend/src/components/jobs/NextStepsCard.tsx`
**Purpose:** Bottom of results page. Agent-generated post-job guidance.
**Anatomy:**
- Card heading: "Recommended next steps" (`text-xl font-semibold`)
- Body: prose text rendered with inline markdown (same regex renderer as existing `AgentMessage.tsx`) at `text-base` weight 400
- No interactive elements — read-only card

### JobCompletionCard (chat inline)
**File:** `frontend/src/components/jobs/JobCompletionCard.tsx`
**Purpose:** Posted by agent into chat thread on job completion. Extends existing chat card pattern.
**Anatomy:**
- Summary row: "# designs generated in N min — $X.XX"
- "View full results" button: `variant="default"`, links to `/jobs/{id}`, accent color (primary variant)

### BindCraftZeroOutputCard
**File:** `frontend/src/components/jobs/BindCraftZeroOutputCard.tsx`
**Purpose:** Replaces CandidateCard list when BindCraft returns 0 designs. Must NOT read as a failure.
**Anatomy:**
- Distinct from the failure card. No destructive colors.
- Heading: "No designs passed filters" (`text-xl font-semibold`)
- Body text (exactly): "BindCraft completed successfully but 0 designs passed the active filters. This is expected behavior when filter criteria are strict. You were charged for GPU compute time consumed."
- Agent guidance block below (same style as NextStepsCard body): suggests loosening parameters.

### JobFailureCard
**File:** `frontend/src/components/jobs/JobFailureCard.tsx`
**Purpose:** Shown on `/jobs/{id}` and in chat when job fails.
**Anatomy:**
- Destructive border accent: `border-destructive/40`
- Failure category label (`text-sm text-muted-foreground`): one of "GPU timeout", "Invalid input", "Provider error"
- Agent guidance block: what to fix before retrying
- No retry button (auto-retry is explicitly out of scope per REQUIREMENTS.md)

### ExpiryWarningBanner
**File:** `frontend/src/components/jobs/ExpiryWarningBanner.tsx`
**Purpose:** Shown at top of `/jobs/{id}` when results are within 7 days of 30-day R2 expiry.
**Anatomy:**
- `variant="default"` shadcn Alert component
- Copy (exactly): "These results expire on [date]. Download your files before then — after expiry, the job record remains but PDB files are permanently deleted."

## Page Layout

### `/jobs/{id}` — JobPage
**File:** `frontend/src/pages/JobPage.tsx`
**Route:** Added to `frontend/src/App.tsx`

**Layout (top to bottom):**
1. ExpiryWarningBanner (conditional — render only when expiring within 7 days)
2. JobStatusCard (always shown — updates in real time while running; static when complete/failed/cancelled)
3. RunSummaryCard (shown only when `status === "complete"` or `status === "cancelled"`)
4. BindCraftZeroOutputCard OR CandidateCard list (shown only when complete)
5. JobFailureCard (shown only when `status === "failed"`)
6. NextStepsCard (shown only when complete and next-steps content exists)

**Max content width:** `max-w-3xl mx-auto` — matches existing ChatPage layout width.
**Top padding:** `pt-8` (32px), **bottom padding:** `pb-12` (48px).
**Card vertical gap:** `space-y-6` (24px between cards).

**Job history list** (bottom of JobPage, below the active job section):
- Simple `<ul>` of past jobs rendered as compact rows with status badge, tool name, date, and link to `/jobs/{id}`
- No sort or filter controls (v2 per JOB-V2-01)
- Section heading: "Previous jobs" (`text-xl font-semibold`)

## Interaction States

### Launch Job flow (BILL-03 gate)

1. User clicks "Launch Job" on ReviewCard
2. Backend checks for Stripe payment method
3. **If no payment method:** redirect to Stripe Checkout (external). On return with `?setup=success` query param, retry launch automatically. On `?setup=cancelled`, show inline alert (shadcn Alert, `variant="default"`): "A payment method is required to launch jobs. Add a payment method to continue."
4. **If payment method exists:** proceed to dispatch. Button enters disabled state with label "Launching..." during async request.

### Cancellation confirm dialog

**Trigger:** "Cancel job" button on JobStatusCard.
**Component:** shadcn Sheet or inline confirm section within card (not a modal overlay — keeps user in context).
**Copy (exactly):**
- Heading: "Cancel this job?"
- Body: "GPU compute will stop immediately. You will be charged for time consumed up to this point."
- Confirm button: `variant="destructive"`, label "Yes, cancel job"
- Dismiss button: `variant="outline"`, label "Keep running"

### Job status SSE reconnect

If the SSE connection drops while job is running (network blip), the client retries the connection silently. If the job has already reached a terminal state by the time SSE reconnects, the page renders the terminal state immediately (no stuck "running" state displayed to user). No user-visible error for SSE drops — use the existing `fetch + ReadableStream` pattern from `frontend/src/lib/agent.ts`.

### Download button loading state

"Download all designs" button enters disabled state with label "Preparing download..." during zip generation. Individual CandidateCard download buttons each have their own loading state independently.
