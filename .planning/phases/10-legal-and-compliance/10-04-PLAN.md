# Plan 10-04: GDPR Data Export + Account Deletion with 30-Day Grace

## Objective

Implement GDPR Article 20 (data portability) via an export endpoint that emails a presigned ZIP, and GDPR Article 17 (erasure) via a soft-delete request with a 30-day grace period followed by a scheduled hard-delete across all subprocessors (Supabase, R2, Stripe).

## Scope

1. DB migration adds `deletion_requested_at TIMESTAMPTZ`, `last_export_requested_at TIMESTAMPTZ`, `last_export_url TEXT`, `last_export_expires_at TIMESTAMPTZ` to `public.users`.
2. `POST /user/data-export` — authenticated; accepts empty body; enqueues a FastAPI BackgroundTask that builds a ZIP, uploads to R2 under `users/{user_id}/exports/export-{timestamp}.zip`, generates a 24hr presigned GET URL, emails the user via Resend, and records `last_export_url` + `last_export_expires_at` on the user row. Rate-limited at 1/hour per user (T-10.04-06).
3. `GET /user/data-export` — returns status of the most recent export (pending / ready / expired / none).
4. `POST /user/delete-account` — authenticated; requires body `{confirmation_phrase: "DELETE MY ACCOUNT"}` as CSRF-like guard; sets `deletion_requested_at = now()` using an atomic conditional UPDATE; writes an `audit_log` row (T-10.04-07); sends a confirmation email with cancel link; returns `{deletion_scheduled_for: <ISO timestamp 30 days out>}`.
5. `POST /user/cancel-deletion` — authenticated; clears `deletion_requested_at`.
6. `backend/worker/deletion_cron.py` — runs daily at 03:15 UTC; for each user with `deletion_requested_at < now() - 30 days`: delete R2 objects, delete Stripe customer, call Supabase Admin `auth.admin.delete_user(uid)` (which cascades `public.users` and all children via `ON DELETE CASCADE`). `execute_hard_delete` re-checks `deletion_requested_at` under `SELECT ... FOR UPDATE` before any destructive action (T-10.04-04).
7. Frontend `PrivacyTab.tsx` wires both actions with confirmation dialogs; added as a new tab to `SettingsPage.tsx` between "Billing" and "Usage". This plan (not 10-02) owns adding `deletion_requested_at` to the `GET /user/settings` response and to the `UserSettings` TypeScript interface.

    def list_and_delete_user_objects(user_id: str) -> int:
        """Enumerate and delete all objects under users/{user_id}/. Returns count deleted.

        Uses list_objects_v2 with Prefix = f"users/{user_id}/" and delete_objects
        batched at 1000 keys per call (S3 API max). Safe to re-run (idempotent);
        raises on permission errors so callers can surface a failed hard-delete.
        """
        client = get_s3_client()
        prefix = f"users/{user_id}/"
        deleted = 0
        paginator = client.get_paginator("list_objects_v2")
        for page in paginator.paginate(Bucket=settings.s3_bucket_name, Prefix=prefix):
            contents = page.get("Contents") or []
            if not contents:
                continue
            keys = [{"Key": obj["Key"]} for obj in contents]
            # S3 delete_objects max 1000 keys per call; paginator already chunks
            resp = client.delete_objects(
                Bucket=settings.s3_bucket_name,
                Delete={"Objects": keys, "Quiet": True},
            )
            deleted += len(keys)
            errors = resp.get("Errors") or []
            if errors:
                logger.error("delete_objects errors for user %s: %s", user_id, errors)
                raise RuntimeError(f"delete_objects reported {len(errors)} errors; see log")
        logger.info("list_and_delete_user_objects: user=%s deleted=%d", user_id, deleted)
        return deleted
    ```

    """Data export builder — invoked as a FastAPI BackgroundTask from POST /user/data-export."""
    import io
    import json
    import logging
    import zipfile
    import datetime
    from typing import Any

    from config import settings
    from db.connection import get_db_pool
    from storage.client import get_s3_client, generate_presigned_get_url
    from jobs.notifications import send_export_ready_email

    logger = logging.getLogger(__name__)

    EXPORT_URL_TTL_SECONDS = 24 * 3600  # 24 hours

    async def build_and_deliver_export(user_id: str, user_email: str) -> None:
        """Build the export ZIP, upload to R2, presign, email, persist metadata.

        Steps:
        1. Pull user profile (all Phase-10 columns), sessions, session_messages, jobs from Postgres.
        2. Serialize to JSON files in an in-memory ZIP with a manifest.json.
        3. Upload to users/{user_id}/exports/export-{ts}.zip.
        4. Presign GET URL (24 hours).
        5. UPDATE public.users SET last_export_url, last_export_expires_at.
        6. Email the user the presigned URL via send_export_ready_email.
        """
        ts = datetime.datetime.now(datetime.timezone.utc).strftime("%Y%m%dT%H%M%SZ")
        key = f"users/{user_id}/exports/export-{ts}.zip"
        expires_at = datetime.datetime.now(datetime.timezone.utc) + datetime.timedelta(seconds=EXPORT_URL_TTL_SECONDS)

        pool = await get_db_pool()
        async with pool.acquire() as conn:
            # Export profile covers every Phase-10-added user column so the user can
            # verify ToS acceptance, retention, deletion state, export history, and
            # (for their own records) their Stripe customer id. No billing PII beyond that.
            profile = await conn.fetchrow(
                """SELECT id, email, display_name, created_at,
                          tos_version, tos_accepted_at,
                          data_retention_days, deletion_requested_at,
                          last_export_requested_at,
                          notification_preferences, stripe_customer_id
                   FROM public.users WHERE id = $1""",
                user_id,
            )
            sessions = await conn.fetch("SELECT * FROM public.sessions WHERE user_id = $1", user_id)
            jobs = await conn.fetch("SELECT * FROM public.jobs WHERE user_id = $1", user_id)
            session_ids = [s["id"] for s in sessions]
            messages = []
            if session_ids:
                messages = await conn.fetch(
                    "SELECT * FROM public.session_messages WHERE session_id = ANY($1::uuid[])",
                    session_ids,
                )

        def _json_default(o: Any) -> Any:
            if isinstance(o, (datetime.datetime, datetime.date)):
                return o.isoformat()
            if hasattr(o, "hex") and callable(getattr(o, "hex", None)):  # UUID
                return str(o)
            return str(o)

        buf = io.BytesIO()
        with zipfile.ZipFile(buf, "w", zipfile.ZIP_DEFLATED) as zf:
            zf.writestr("profile.json", json.dumps(dict(profile), default=_json_default, indent=2))
            zf.writestr("sessions.json", json.dumps([dict(r) for r in sessions], default=_json_default, indent=2))
            zf.writestr("session_messages.json", json.dumps([dict(r) for r in messages], default=_json_default, indent=2))
            zf.writestr("jobs.json", json.dumps([dict(r) for r in jobs], default=_json_default, indent=2))
            referenced_keys = [j["pdb_path"] for j in jobs if j.get("pdb_path")]
            zf.writestr("manifest.json", json.dumps({
                "generated_at": ts,
                "user_id": user_id,
                "referenced_object_keys": referenced_keys,
                "notes": "PDB input files and job outputs remain in object storage; their S3 keys are listed here. If you need the files themselves, contact privacy@ranomics.com.",
            }, indent=2))
        buf.seek(0)

        s3 = get_s3_client()
        s3.put_object(Bucket=settings.s3_bucket_name, Key=key, Body=buf.getvalue(), ContentType="application/zip")
        presigned_url = generate_presigned_get_url(key, expires_in=EXPORT_URL_TTL_SECONDS)

        async with pool.acquire() as conn:
            await conn.execute(
                """UPDATE public.users
                   SET last_export_requested_at = now(),
                       last_export_url = $2,
                       last_export_expires_at = $3,
                       updated_at = now()
                   WHERE id = $1""",
                user_id,
                presigned_url,
                expires_at,
            )

        await send_export_ready_email(user_email, presigned_url, expires_at.isoformat())
        logger.info("Export delivered for user=%s key=%s", user_id, key)
    ```

    2. Create `backend/user/deletion.py`:
    ```py
    """Account deletion soft-delete handler + hard-delete executor.

    Soft-delete: POST /user/delete-account sets deletion_requested_at = now().
    Hard-delete: executed by worker/deletion_cron.py once grace period expires.
    """
    import logging
    import datetime

    import stripe

    from db.connection import get_db_pool
    from storage.client import list_and_delete_user_objects
    from auth.admin_client import delete_auth_user
    from jobs.notifications import send_deletion_completed_email

    logger = logging.getLogger(__name__)

    GRACE_PERIOD_DAYS = 30

    async def execute_hard_delete(user_id: str, user_email: str, stripe_customer_id: str | None) -> None:
        """Execute the permanent deletion flow for one user.

        Race guard (T-10.04-04): FIRST step re-acquires the row under SELECT ... FOR UPDATE
        and aborts if deletion_requested_at is NULL (user cancelled between cron fetch and
        executor). This prevents deleting a user who raced a cancel in before the cron ran.

        Order matters after the guard passes:
        1. Delete R2 objects under users/{user_id}/ — no downstream references once gone.
        2. Delete or anonymize Stripe customer — invoices retained per tax law (7yr), PII detached.
        3. Delete Supabase auth.users row — cascades public.users + all FK children.
        4. Send final deletion-completed email (best effort; user no longer in DB).
        """
        # 0. Race guard (T-10.04-04) — abort if the user cancelled deletion in the meantime.
        pool = await get_db_pool()
        async with pool.acquire() as conn:
            async with conn.transaction():
                guard_row = await conn.fetchrow(
                    "SELECT deletion_requested_at FROM public.users WHERE id = $1 FOR UPDATE",
                    user_id,
                )
                if guard_row is None or guard_row["deletion_requested_at"] is None:
                    logger.warning(
                        "execute_hard_delete: aborting user=%s — deletion_requested_at is NULL "
                        "(user cancelled or row missing).",
                        user_id,
                    )
                    return

        # 1. R2
        try:
            count = list_and_delete_user_objects(user_id)
            logger.info("Hard-delete: user=%s deleted %d R2 objects", user_id, count)
        except Exception as exc:
            logger.error("Hard-delete R2 failure user=%s: %s", user_id, exc)
            raise  # do not proceed — partial delete is worse than no delete

        # 2. Stripe — detach PII. We delete the Customer per decision D-04 in 10-CONTEXT.md;
        #    Stripe retains invoice records regardless. For accounts with no charges, Customer.delete succeeds.
        if stripe_customer_id:
            try:
                stripe.Customer.delete(stripe_customer_id)
                logger.info("Hard-delete: Stripe customer deleted %s", stripe_customer_id)
            except Exception as exc:
                logger.warning("Hard-delete Stripe customer %s failed (continuing): %s", stripe_customer_id, exc)
                # Do not raise — invoice retention requirements may block full delete; log and continue.

        # 3. Supabase auth + cascade
        delete_auth_user(user_id)
        logger.info("Hard-delete: Supabase auth user deleted %s", user_id)

        # 4. Final email (best effort; row is already gone but we still have email)
        try:
            await send_deletion_completed_email(user_email)
        except Exception as exc:
            logger.warning("Hard-delete final email failed for %s: %s", user_email, exc)
    ```

## Threat Model

Trust boundaries: (1) authenticated browser → /user/data-export + /user/delete-account + /user/cancel-deletion; (2) BackgroundTask → R2 + Resend; (3) cron (service role) → Supabase Admin + Stripe + R2.

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10.04-01 | Elevation of Privilege (account-takeover via export) | POST /user/data-export | mitigate | Endpoint requires `Depends(get_current_user)` (validates Supabase JWT from HTTP-only cookie). Presigned URL is emailed ONLY to the email stored on the user row (not to an attacker-chosen address). 24hr URL TTL bounds the window. Future hardening: require re-auth (fresh password) — out of scope v1. |
| T-10.04-02 | Tampering (CSRF mass-deletion) | POST /user/delete-account | mitigate | Global `CSRFMiddleware` (starlette_csrf double-submit pattern from main.py:63-70) already protects all POST endpoints. Additional defense: requires exact literal `confirmation_phrase: "DELETE MY ACCOUNT"` in JSON body — cannot be triggered by a GET image or trivial form POST. |
| T-10.04-03 | Information Disclosure (IDOR on export) | build_and_deliver_export | mitigate | The export SELECT filters by `user_id = $1` where $1 comes from the authenticated JWT via get_current_user — not from any request field. Presigned URL is scoped to a key under `users/{user_id}/exports/` (per-user prefix). No user-supplied path segments. |
| T-10.04-04 | Race (soft-delete grace vs reactivation) | cron + /user/cancel-deletion | mitigate | Cron query filters `deletion_requested_at IS NOT NULL AND deletion_requested_at < NOW() - INTERVAL '30 days'`. /user/cancel-deletion sets `deletion_requested_at = NULL`. If the user cancels between cron fetch and execute_hard_delete, **execute_hard_delete's first step re-checks the row under `SELECT deletion_requested_at FROM public.users WHERE id = $1 FOR UPDATE` inside a transaction; if NULL, aborts with a warning log and no destructive calls**. Implemented as step 0 in user/deletion.py execute_hard_delete. |
| T-10.04-05 | Data Persistence (partial delete) | execute_hard_delete | mitigate | Order: R2 → Stripe → Supabase. If R2 fails, abort BEFORE auth delete (row stays, retried next cron). If Stripe fails, log and continue (invoice retention legally required). If Supabase auth.admin.delete_user fails, the public.users row persists — cron retries. Idempotent by design: list_and_delete_user_objects on an already-empty prefix returns 0 without error. |
| T-10.04-06 | Denial of Service (export spam) | POST /user/data-export | mitigate | Pydantic endpoint is cheap on the API side (just schedules a BackgroundTask).
