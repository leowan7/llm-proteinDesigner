# Plan 10-06: Legal Routes + Persistent Footer + Settings Navigation

## Wave & dependency note

This plan edits `frontend/src/App.tsx` to add `/legal/*` routes. Plan 10-03 also edits `App.tsx` (to wrap the Routes tree with `<CookieConsentProvider>`). Wave sequencing:

- Wave 1: 10-02, 10-03 (parallel — disjoint files)
- Wave 2: 10-04, 10-06 (parallel — disjoint files; 10-06 depends on 10-03 from wave 1)
- Wave 3: 10-05

This plan depends on 10-03 so its App.tsx route additions land sequentially AFTER 10-03's provider wrap — no merge race.

## Objective

Expose the four legal pages from Plan 10-01 as public routes under `/legal/*`, render a persistent footer on every screen (authenticated and unauthenticated) linking to all four pages plus a "Cookie preferences" trigger, and add deep-link support to the Privacy tab of SettingsPage.

## Scope

1. Four public routes in `App.tsx` (outside any auth-gated layout):
   - `/legal/terms` → `<Terms />`
   - `/legal/privacy` → `<Privacy />`
   - `/legal/subprocessors` → `<Subprocessors />`
   - `/legal/cookies` → `<Cookies />`
2. New `AppFooter` component:
   - Links to Terms, Privacy, Subprocessors, Cookies.
   - "Cookie preferences" button calling `requestOpenConsent()` from `@/lib/cookieConsent`.
   - "© {current_year} Ranomics Inc." copyright.
3. Footer mounted inside:
   - `AuthenticatedLayout.tsx` (below `<main>`, visible on /chat, /jobs, /settings, /admin/*).
   - `AuthLayout.tsx` (below AuthLayout content, visible on /login, /signup, /verify-email, etc.).
4. `AppSidebar.tsx` Settings nav link updated to point to `/settings?tab=privacy` when the context menu option is "Privacy" (optional nicety — or leave Settings pointing at /settings and rely on SettingsPage reading the URL param).
5. `SettingsPage.tsx` reads `?tab=` query param via `useSearchParams` and sets the initial Tabs value; defaults to "account".
6. Vitest coverage for the `?tab=privacy` deep-link path (hardens the cancel-deletion email link from Plan 10-04 Task 3).
